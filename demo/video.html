Video Component

Embeds Kaltura or YouTube video. Kaltura embeds use Kaltura's Dynamic Embed method (a generated <div> plus KalturaPlayer.setup()), which is what Kaltura's own Share & Embed dialog produces.

Kaltura videos show a thumbnail and play button until clicked; nothing is fetched or loaded until then. On click, the video plays with a real, user-attributed Kaltura session when it can get one (falling back to anonymous playback if that fails for any reason), so plays show up against the actual viewer in Kaltura's own reporting instead of "Unknown". See Kaltura analytics for what is recorded.

Add the component bundle before </body>.

A single Kaltura video

Pass the Kaltura entry ID as videoid. Nothing else is required; the standard UGA Online player is used by default.

<uga-video videoid="1_icw0df6y"></uga-video>

Branded players

Set playerid to the uiConf ID, the number after uiconf_id/ in a Kaltura embed code. That is what carries program or college branding and end cards. Omit it for the standard UGA Online player (57494843). Each distinct player on a page loads its own player bundle, so prefer one player per page unless the branding genuinely differs — which is why this example is not rendered live here.

<uga-video videoid="1_icw0df6y" playerid="53568732"></uga-video>

YouTube videos

Set host="youtube" and pass the ID from the YouTube URL. For https://www.youtube.com/watch?v=yx3bxPfbdRM the ID is yx3bxPfbdRM.

<uga-video host="youtube" videoid="yx3bxPfbdRM" name="YouTube Demo"></uga-video>

Multiple videos on one page

Use one <uga-video> per video, each with its own videoid. Nothing is fetched or loaded for a given video (no Kaltura player script, no attribution session) until its play button is actually clicked, so a page with several videos doesn't pay for the ones nobody watches.

<uga-video videoid="1_icw0df6y"></uga-video> <uga-video videoid="1_p658t55u"></uga-video>

Kaltura analytics

When a viewer clicks play on a page inside an eLC course, the component asks UGA Online's identity service for a view-only Kaltura session tied to that viewer. Kaltura then records the play under the viewer's eLC username. Nothing needs to be added to the tag; this happens for every Kaltura video.

This matters because Kaltura counts every anonymous viewer as a single viewer. Without attribution, a video watched by forty students reports one unique viewer, and the per-user reports in Kaltura have nobody to list. With it, each student appears separately, with their own plays, completion rate, and a heatmap of which parts they watched.

What gets recorded

  • The viewer's eLC login username, which is their UGA MyID. The component reads it from eLC's record of who is signed in. It does not send the numeric eLC user ID or the student ID number.
  • The course, as a referrer address built from the course's org unit ID (/d2l/le/content/ou/). eLC's content viewer does not show the real content item in the page address, so the component sets this itself. In Kaltura it appears under the eLC domain in the Top domains list of the Engagement dashboard, and clicking the domain lists the page URLs, one per course.
  • Kaltura's standard viewing statistics for the play, which come from Kaltura's own player. The component does not collect or store viewing data itself.

Reading the numbers

Definitions below follow Kaltura's analytics terminology. The last column notes where uga-video changes how a number should be read.

Kaltura analytics metrics and how uga-video affects them
Metric How Kaltura counts it With uga-video
Plays One play each time playback starts, whether from the Play button or autoplay. Pausing and resuming does not add a play. The player starts as soon as the viewer clicks the thumbnail, so each click on a video's play button counts as one play.
Player impressions One impression each time the player loads on a page, whether or not anyone presses play. The player loads only after the click, so impressions and plays come out nearly equal. The impression-to-play ratio does not show how many students opened the page and skipped the video.
Unique viewers Distinct signed-in viewers. All anonymous viewers count as one. Kaltura estimates this figure, and it can differ from exported reports by about 2%. Accurate only for attributed plays. Anything that fell back to anonymous playback adds at most one viewer.
Minutes viewed Counted by quartile milestones, not seconds. Watching 4 minutes of a 10-minute video counts as 2.5 minutes (the 25% mark). No change.
Completion rate Average completion is the average percentage watched per play. Total completion, shown per user, counts each part of the video once across all of that user's plays, so watching the first half one day and the second half the next is 100%. Per-user completion needs attribution; for anonymous plays only the averages are meaningful.

Where to see it

The data lives in Kaltura, not eLC. For one video:

  • In the Kaltura Rich Media CMS (formerly KMC), go to Content > Entries, open the entry, and click View Analytics.
  • In MediaSpace or the Kaltura tools in eLC, open My Media, open the entry, and choose Analytics from the Actions menu.

On the entry's dashboard, View Engagement Per User lists each viewer with their plays, player impressions, and completion rates, and the arrow next to a name opens a heatmap of the parts they watched. Clicking a username anywhere in the analytics opens that user's own dashboard across all videos. The account-wide dashboards under the Rich Media CMS Analytics menu (Engagement, Category, and others) are for Kaltura administrators. See Kaltura analytics and Entry level analytics in Kaltura's documentation.

Kaltura notes that privacy and ad-blocking browser extensions can stop its analytics from being collected, so some plays may be missing even when attribution worked.

The component does not write anything to the eLC gradebook or mark content topics complete; use eLC's own completion tracking for that. Viewing records tied to a named student are education records under FERPA, so share them only with people who have a legitimate need and follow UGA policy when exporting them.

When a play stays anonymous

Attribution never blocks the video. If any step fails, the video plays anonymously, and the browser console logs uga-video: falling back to anonymous Kaltura playback. That happens when:

  • the page is not open inside an eLC course by a signed-in user (for example, a local preview or a public page);
  • eLC does not return the signed-in user, or the course ID cannot be found (set ou if the page's address does not include it);
  • the identity service returns an error or does not answer within 6 seconds.

YouTube videos are not covered. Nothing about a YouTube play is sent to Kaltura.

Attributes

uga-video attributes
Attribute Type Default Description
videoid string empty Kaltura entry ID, or YouTube video ID when host="youtube". Required.
host string empty Set to youtube for a YouTube embed. Leave it off for Kaltura.
playerid string 57494843 Kaltura uiConf ID, which selects the player and therefore the branding and end cards. Omit for the standard UGA Online player.
name string empty Video title, used as the play button's accessible label and the YouTube iframe title.
ou string empty eLC org unit (course) ID, also used to attribute plays to the course in Kaltura. Only needed if it can't be parsed from the page's own URL; leave it off in normal course content.
