Setup & Usage

Complete guide to setting up and using UGA Lit Components in eLC.

This page covers installation, configuration, and data file creation for all components.

Demo HTML pages in this folder link to demo-inline-code.css so filenames and inline <code> in callouts match surrounding text size. Individual demos also link back here for the full checklist.

How to Use These Components in eLC

1. Add to Your Page

Create a new HTML page in eLC and add your components:

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>My Page</title> <link rel="stylesheet" href="https://design.online.uga.edu/css/base.css"> </head> <body> <h1>My Course Content</h1> <!-- Your components --> <uga-accordion type="local" filename="my-accordion.json"></uga-accordion> <uga-video videoid="1_icw0df6y"></uga-video> <uga-image src="image/photo.jpg" alt="Description" caption="Optional caption"></uga-image> <!-- Load bundle at end of page --> <script type="module" src="/shared/ugaonline/js/uga-components.js"></script> </body> </html>

Production (eLC): Use src="/shared/ugaonline/js/uga-components.js". Ensure the bundle is deployed to that path for instructional designers.

2. Create Data Files (for components that need them)

Many components load data from JSON files. The uga-quiz component loads questions from JSON by default (type="local"); CSV is optional via type="csv". Upload files to eLC course files and reference them with a relative filename when the file is next to your HTML, or use the full path from Manage Files.

How to find the file path in eLC:

  1. Go to Content → Manage Files (or Course Admin → Manage Files)
  2. Upload your JSON file
  3. Right-click the file and select View File Path or Copy Path
  4. The path will look like: /content/enforced/12345-123456/your-file.json
  5. Use this full path in your component's filename attribute

Note: JSON files don't display visually in eLC - they're loaded by components in the background for configuration purposes.

Example: accordion/accordion-demo.json

{ "title": "Course FAQ", "data": [ { "title": "How do I submit assignments?", "body": "<p>Go to the Assignments page and click Submit.</p>" }, { "title": "When are office hours?", "body": "<p>Tuesday and Thursday, 2-4 PM EST.</p>" } ] }

Example: tabs/tabs-demo.json

{ "data": [ { "title": "Overview", "body": "<p>This module covers...</p>" }, { "title": "Learning Objectives", "body": "<ul><li>Objective 1</li></ul>" } ] }

Example: circles/circles-demo.json

{ "data": [ { "figure": "85%", "caption": "Pass Rate" }, { "figure": "150", "caption": "Students Enrolled" } ] }

Example: slideshow/slideshow-demo.json

{ "data": [ { "image": "/shared/PublicFiles/images/slide1.jpg", "caption": "Introduction to the course" }, { "image": "/shared/PublicFiles/images/slide2.jpg", "caption": "Key concepts overview" } ] }

Example: footer/footer-demo.json

{ "data": { "link": "https://online.uga.edu", "alt": "University of Georgia Online Learning Logo", "imageSrc": "https://design.online.uga.edu/images/uga-logo.png" } }

Use filename="footer/footer-demo.json" when the JSON sits under a footer/ folder next to your HTML page (or the full path from Manage Files). Use program="…" or name="…" with the same abbreviated template code (e.g. msw, acct, mfp, terry for Terry College of Business); data loads from /shared/ugaonline/templates/{code}/data/footer.json. A full list of codes and logo paths is on the Footer demo page (including mfp → /shared/ugaonline/templates/mfp/img/MFP_logo_Horizontal_CW.png and terry → /shared/ugaonline/templates/terry/img/TERRY_logo_Banner_CW.png).

Example: course-calendar/course-calendar-demo.json

{ "data": { "weeks": [ { "label": "Week 1 - May 12-18 - Classes Begin", "rows": [ { "type": "open", "date": "May 12", "day": "Tuesday", "moduleTitle": "Modules 00, 01 and 02 Open", "moduleItems": ["M00: Welcome and Introduction"], "event": "Classes Begin", "notes": "First day of instruction." } ] } ] } }

Use <uga-course-calendar type="local" filename="course-calendar/course-calendar-demo.json"></uga-course-calendar> to render the table. Put titles and intro copy in page HTML. Optional caption sets the table caption. Add sync-from-course (or legacy sync-due-status) only when rows include dueTags with folderId for assignment sync.

CSV option: You can use type="csv" with a flat file that includes weekLabel on each row. Use course-calendar/course-calendar-template.csv as a starter template.

<uga-course-calendar type="csv" filename="course-calendar/course-calendar-demo.csv"></uga-course-calendar> <uga-course-calendar type="csv" filename="course-calendar/course-calendar-demo.csv" sync-from-course> </uga-course-calendar>

CSV columns: required: weekLabel, rowType, date, day, event. Optional: moduleTitle, moduleItems, notes, noteHint, rowDate, dueTags, folderIds. Use pipe separators for multi-values (|), with dueTags and folderIds position-matched.

Example: instructor-note/instructor-note-demo.html

The instructor note is an HTML fragment (not JSON). Save the markup below under instructor-note/instructor-note-demo.html (or any path/filename you prefer) and reference it with filename:

<div style="background-color: #fff3cd; padding: 1rem; border-left: 4px solid #ffc107; margin: 1rem 0;"> <h4 style="margin-top: 0; color: #856404;">📝 Instructor Note</h4> <p><strong>This content is only visible to instructors and teaching assistants.</strong></p> <ul> <li>Grading tip 1</li> <li>Common misconception to address early</li> </ul> </div>

Reference it with <uga-instructor-note type="local" filename="instructor-note/instructor-note-demo.html"></uga-instructor-note> when the file lives under instructor-note/ next to your page.

Example: videos/videos-demo.json (for multiple videos)

{ "data": [ { "videoid": "1_abc123de", "title": "Introduction Video" }, { "videoid": "1_xyz789fg", "title": "Lecture 1" } ] }

Quiz component: JSON or CSV file

The uga-quiz component can load questions from either a JSON file (component format) or an eLC CSV question-import file. Use type="local" for JSON or type="csv" for CSV, and point filename at the file.

JSON format: The file must have a top-level questions array. Each question has id, type, question, points, correctAnswer, and optionally options, explanation, caseSensitive. See docs/QUIZ_JSON_FORMAT.md for the full format and examples.

CSV format: Use the eLC question-import layout (the same one Brightspace produces when you export a question library). Each question is a block of rows beginning with NewQuestion,<type> (MC, TF, SA/WR, M, MS, O) followed by QuestionText, Points, and the type-specific rows (Option, TRUE/FALSE, Answer, Choice/Match, Item). Lines starting with // are ignored. See quiz/quiz-sample.csv for a full template covering all six types.

Steps (JSON): (1) Create a JSON file with a questions array (templates: quiz/quiz-sample.json, quiz/quiz10.json, quiz/quiz20.json). (2) Upload it to course files (a quiz/ folder next to your HTML works well). (3) Set type="local" and filename to the relative path or full path from Manage Files.

Steps (CSV): (1) Export questions from eLC's question library as CSV, or hand-author a file using quiz/quiz-sample.csv as a template. (2) Upload it to course files. (3) Set type="csv" and filename to the relative or full path. See the Quiz demo for full usage of both options.

3. Component-Specific Setup

Components that do not require eLC API access

  • uga-callout - Semantic callout block (note, important, tip, example, warning) with an optional bolded label. Uses slot content and renders as <aside>. See Callout demo.

eLC API Components

These components require eLC API access and will only work in eLC:

  • uga-assignment - Displays assignments, discussions, quizzes, and content with due dates from the current eLC course. By default, all item types are displayed. Use the types property to filter (e.g., types="assignment,discussion"). Supports grade export when enable-export is set.
  • uga-duedate - Displays due dates for assignments, discussions, quizzes, and content in a formatted table. By default, all item types are displayed. Use the types property to filter (e.g., types="assignment").
  • uga-quiz - Embed formative quizzes; loads questions from a JSON file (type="local", filename) or eLC question-import CSV (type="csv", filename). Can submit results to an eLC assignment. See Quiz demo, quiz/quiz-sample.json, and quiz/quiz-sample.csv.
  • uga-course-calendar - Renders a week-by-week calendar from JSON or CSV (type="local" | "csv" | "program"). Optional sync-from-course (legacy alias sync-due-status) updates date cells from live assignment due dates using dueTags[].folderId.
  • uga-quiz-grade-sync - Instructor-only button to sync quiz submissions to the gradebook. Place below the quiz (or inside an instructor note); set dropbox-assignment-name (e.g. "Quiz Demo 2") or dropbox-folder-id to the assignment folder ID.
  • uga-course-analytics - Course-wide analytics aggregating data from content, assignments, and discussions. Shows module-level consumption statistics and comparisons. Does not enforce its own role check—hide the embedding page from students with eLC release conditions. See Course Analytics demo.
  • uga-elc-google-sync - Admin-only: template export to Google Drive / clear / back-copy (MVP: read-only preview). Configure admin-role-names or admin-role-ids; use stub-mode for demos. See docs/ELC_GOOGLE_SYNC_WIDGET.md and eLC ⇄ Google Sync demo.
  • uga-instructor-note - Visible only to instructors (uses eLC role checking)
  • uga-rating - Stores ratings in eLC forums

Quiz & Grade Sync

For the quiz and automatic grade sync:

  • Create an assignment in eLC to receive quiz submissions (e.g. Quiz Demo 2).
  • Make the assignment visible to students (e.g. in Assignments → assignment → Edit → Restrictions). If the assignment is hidden, the quiz component cannot find it and submissions will not pass through.
  • Set the assignment to allow Text or File submissions so it can accept the quiz result (submitted as text/JSON or as a .json file).
  • Link the assignment to a grade item in the gradebook so the sync button can push grades. When synced, the most recent grade overwrites any current grade for each student.
  • Place the grade sync component below the quiz (or inside an instructor note). Use <uga-instructor-note type="local" filename="quiz/quiz-sync-note.html"></uga-instructor-note> to wrap the sync button, or place <uga-quiz-grade-sync dropbox-assignment-name="Quiz Demo 2"> (or dropbox-folder-id="folderId") directly below the quiz so instructors can run "Sync quiz grades to gradebook."

Example with instructor note wrapper:

<uga-quiz quiz-id="quiz-1" quiz-title="My Quiz" passing-score="70" type="local" filename="quiz/quiz-sample.json" dropbox-assignment-name="Quiz Demo 2"> </uga-quiz> <uga-instructor-note type="local" filename="quiz/quiz-sync-note.html"></uga-instructor-note>

The instructor note file (quiz/quiz-sync-note.html) contains the grade sync component. See quiz/quiz-sync-note.html for the file content.

Course Analytics

The uga-course-analytics component provides course-wide analytics by aggregating data from multiple sources:

  • Content: Module/topic views and completions
  • Assignments: Submission rates and scores
  • Discussions: Post counts and participation
  • Other course data: Objectives, login history, average final grade (from eLC APIs)

Usage:

<!-- Show all analytics (default) --> <uga-course-analytics></uga-course-analytics> <!-- Show only content and assignment stats --> <uga-course-analytics show-content-stats="true" show-assignments="true" show-discussions="false"> </uga-course-analytics>

Properties:

  • show-content-stats (boolean, default: true) - Show content view/completion statistics
  • show-assignments (boolean, default: true) - Show assignment submission statistics
  • show-discussions (boolean, default: true) - Show discussion participation statistics
  • group-by (string, default: module) - Grouping for analytics: module, topic, or all (currently only module is implemented)
  • compare-modules (boolean, default: true) - Enable module comparison view with visual indicators

Note: This component does not perform its own role check. Hide the embedding page from students using eLC release conditions. It makes multiple API calls to aggregate data, so loading may take several seconds for large courses.

Assignment & Due Date Components - Type Filtering

Both uga-assignment and uga-duedate support filtering by item type:

<!-- Show all types (default) --> <uga-assignment></uga-assignment> <!-- Show only assignments --> <uga-assignment types="assignment"></uga-assignment> <!-- Show assignments and discussions --> <uga-assignment types="assignment,discussion"></uga-assignment> <!-- Show only discussions --> <uga-duedate types="discussion"></uga-duedate>

Available types: assignment, discussion, quiz, content

Kaltura Video Component

For uga-video, you'll need:

  • videoid - The Kaltura entry ID (found in Kaltura MediaSpace)
  • playerid (optional) - Kaltura player / uiConf ID (default: 53568732; copy from Kaltura embed code)
  • topic-id (optional) - eLC content topic ID for completion tracking (uses Playkit JS instead of iframe)
  • uiconfid (optional) - UI configuration ID for custom player appearance

4. Troubleshooting

Components Not Showing

  • Verify the script tag is at the end of your HTML (before closing </body>)
  • Check browser console for errors (F12)
  • Ensure the bundle path is correct: /shared/ugaonline/js/uga-components.js

Data Not Loading

  • Verify JSON file paths are correct relative to Public Files
  • Check JSON syntax is valid (use a JSON validator)
  • For uga-quiz: create a JSON file with a questions array (see docs/QUIZ_JSON_FORMAT.md), upload it, then set type="local" and filename to the file path (filename only if same folder as the page, or full course-files path)
  • Ensure files are uploaded to the correct location in eLC

Accordion Icons Not Showing

  • Add class="js" to your <html> tag: <html lang="en" class="js">
  • This enables the UGA CSS pseudo-element styles for accordion icons

eLC API Errors

  • These components only work inside eLC
  • Verify you're testing in the eLC environment, not locally
  • Check browser console for specific API error messages
